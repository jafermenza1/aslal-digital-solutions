# P8.3 — Cross-Channel Attribution

## Objective

P8.3 makes the existing referral identity portable across Website, Partner Marketplace, and Telegram without introducing a second attribution or commission system.

## Canonical rule

A partner attribution link remains the single source of referral identity:

Website `/go/{code}` → browser referral cookie → lead/order attribution

Partner Marketplace share link → same `/go/{code}` or Telegram `t.me/<bot>?start={code}`

Telegram `/start {code}` → workspace-scoped Telegram identity + visitor → same referral code → lead/order attribution

Telegram Mini App catalog → optional `ref={code}` → validated against the same referral link → identity continuity.

## Partner Telegram login decision

A separate Telegram partner-login system is not added in P8.3 because the repository already has a partner Telegram connection and validated Telegram website login flow. Telegram is treated as an authenticated/attributed channel, not a second partner-account system.

## Security

- Referral codes are resolved inside a workspace.
- An active partner is required.
- Telegram `ref` cannot select another workspace.
- Telegram connection ID and workspace ID must match.
- Business A attribution cannot expose Business B private data.
- Attribution is reused; commissions remain governed by P3–P7.

## Acceptance scenarios

1. Partner generates a Website referral link.
2. Customer visits `/go/{code}` and receives the normal attribution cookie.
3. Partner generates the Telegram deep link for the same commercial item.
4. Customer opens the Telegram deep link and `/start {code}` records the same referral identity.
5. Telegram catalog opens with `ref={code}` when launched from a referral context.
6. Telegram rejects a referral code belonging to another workspace.
7. A Telegram lead retains the same referral code and visitor identity.
8. Order/payment/commission continue through the existing P3–P7 pipeline.
9. A partner connected to Telegram uses the existing workbench without a duplicate partner account.
10. Business A cannot read or use Business B's referral context.
