# P8.1 — Multi-Business Telegram Commerce

## Purpose
P8.1 extends the P8 multi-business marketplace so Telegram is a workspace-owned commerce channel rather than a single global Aslal bot/catalog.

## Ownership rule
Every Telegram commerce request must resolve a single Aslal workspace before reading catalog, customer, partner, lead, order, payment, or automation data. A partner may participate in multiple workspaces; Telegram context does not use the partner's home workspace as a substitute for the target business.

## Implemented foundation
- TelegramBusinessConnection stores workspace-scoped connection metadata.
- Connection types are BOT and BUSINESS.
- Connection lifecycle is PENDING, ACTIVE, DISABLED, ERROR.
- Actual bot secrets are not stored in the database. Dedicated bot connections reference a deployment environment variable name.
- Telegram Business connection IDs are unique and map inbound Business Connection updates to a workspace.
- Telegram Channel Configuration remains workspace-scoped.
- Telegram Catalog uses existing Product and Resource records as the source of truth; it does not create a duplicate product database.
- Catalog requests can carry connectionId, which resolves the owning workspace and rejects workspace/connection mismatches.
- Partner marketplace share links can target a participating business workspace and return a business-specific Telegram deep link when an active Telegram bot connection has a username.
- Telegram /start referral links can resolve an active partner referral link, remember referral context in the Telegram public session, and carry referral_code into the canonical lead when a lead is created.
- Telegram Business connection update events are persisted and associated with the owning workspace.
- Business messages resolve their workspace from business_connection_id before the existing public/client/partner workflows continue.

## UI
Business users with telegram.view/telegram.manage access open /dashboard/telegram and see Sales, Public Experience, Qualification, Catalog / Mini App, Business Channels, Knowledge Base, Payments, and Human Handoff.

The Business Channels panel shows only the selected workspace's connections and supports adding, activating, and disabling a connection. It explicitly tells administrators not to place bot secrets in the database.

## Catalog model
Product and Resource remain canonical. Telegram is a presentation and transaction channel:

Workspace → Product/Resource → Telegram Catalog → Lead/Order → Payment → Revenue → Commission

No Telegram-specific commission ledger is created.

## Partner flow
Partner → business participation → share link → Telegram deep link → referral context → Telegram identity → Lead → Opportunity/Order → existing P3/P6/P7 attribution and financial lifecycle.

Affiliate/influencer, referral agent, and reseller semantics remain separate. Telegram origin does not convert a reseller order into an affiliate commission.

## Provider boundary
Telegram Business connections are supported as a platform integration boundary. Telegram sends business connection IDs and business-message updates to the bot; Aslal maps those IDs to workspaces. Actual Telegram credentials, BotFather configuration, permissions, webhook registration, and provider-specific secret management remain deployment responsibilities.

## Not falsely claimed as complete
The P8.1 foundation does not claim live multi-bot credential provisioning or automatic Telegram account authorization. Dedicated bot execution still requires the configured environment secret and webhook registration. Business-account sending must preserve Telegram's required business connection context and rights. Those provider-runtime checks belong to controlled acceptance.

## Runtime certification
Run on the deployment branch:

npx prisma generate
npx prisma migrate deploy
npm run typecheck
npm run lint
npm test

Then perform two-business acceptance:
- Business A has connection A and catalog A.
- Business B has connection B and catalog B.
- A connection cannot request B's catalog through a mismatched workspaceId.
- A partner participating in both businesses can generate separate business-specific Telegram links.
- A referral deep link from A creates/continues attribution in A, not B.
- Business A administrators cannot list or mutate B's Telegram connections.
- A Telegram Business update with connection A resolves to A's workspace.
